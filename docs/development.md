# Development and verification

The [root POM](../pom.xml) sets Java **25** and Spring Boot **4.1.1**. Use JDK 25 and run Maven from the repository root. The [wrapper configuration](../.mvn/wrapper/maven-wrapper.properties) pins Maven 3.9.12.

## Maven commands

```sh
./mvnw clean verify
./mvnw -pl media -am verify
./mvnw -pl feed -am test
./mvnw -pl feed -am -Dtest=FeedServiceTest -Dsurefire.failIfNoSpecifiedTests=false test
```

The Unix wrapper is tracked without the executable bit. Use `sh ./mvnw` in place of `./mvnw` on a fresh checkout. On Windows, use `mvnw.cmd`.

- `-pl` selects reactor modules and `-am` adds their upstream dependencies. It does not select downstream consumers. Run the full reactor after changing shared contracts, dependencies or application wiring.
- `test` runs Surefire tests. Use a targeted test while iterating, then run the module suite. In the single-class example, the Surefire flag lets upstream modules with no matching class pass. Confirm the requested class ran in the selected module's `target/surefire-reports/`.
- For tests that start PostgreSQL via Testcontainers, provide a working Docker-compatible container runtime. Report environment failures and any verification you could not complete.

## CI and security checks

[CI/CD](../.github/workflows/main.yaml) runs on pull requests targeting `main`, pushes to `main`, and manual dispatch.

- [Build and Sonar](../.github/workflows/build-tests-sonar.yml) runs Maven clean install and SonarCloud analysis on JDK 25, publishes Surefire reports, uploads the app JAR and submits the Maven dependency graph. The root POM points Sonar at the aggregate JaCoCo report generated by `app`.
- [CodeQL](../.github/workflows/codeql.yml) performs Java code scanning. [Docker and Trivy](../.github/workflows/docker-build-scan-push.yml) build the image after build and CodeQL, scan for high and critical vulnerabilities with fixes available, and upload SARIF to GitHub Security. Image push and deployment are push-only.
- Qodana has a workflow definition, but its invocation in CI/CD is currently disabled.
- Keep tests, coverage reporting and scans enabled when fixing a failure. Review the root POM's security version overrides before changing managed dependencies. Use environment variables or CI secrets for credentials and keep real values out of commits.

## Checks before editing

- **HTTP access.** [SecurityConfig](../identity/src/main/java/ua/nin/identity/auth/config/SecurityConfig.java) selects a public or protected filter chain. When changing a route or method, check the matcher, authentication and CORS behavior and the relevant controller and security tests.
- **Schema ownership.** Hibernate uses `ddl-auto: validate`. Add a new Liquibase changeset for schema changes, preserve applied changesets and verify the module master includes the new one. Check native queries, foreign keys and the root changelog order when touching shared keys or schemas.
- **Feed behavior.** Check `VideoFeedQueryPort` and the statistics ports when changing sorting, pagination or response fields. The media query selects the page, and `FeedService` enriches it with counts.
